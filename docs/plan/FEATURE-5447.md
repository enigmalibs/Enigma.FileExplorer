# FEATURE-5447 — Windows MSI build script

**Status:** DONE
**Type:** FEATURE
**Branch:** one per phase, see below
**Run:** feature/2026-11-03-icons-msi-release

## Objective

One command builds the Windows installer, as in Enigma.GitClient (FEATURE-EAB7). Running
`packaging/windows/buildmsi.ps1` (or its `buildmsi.bat` twin):

1. cleans the repository;
2. publishes the release;
3. builds `artifacts/Enigma.FileExplorer.X.Y.Z.msi` with Enigma.Msi.

The MSI is named "Enigma File Explorer", has its own upgrade code, and takes its version from
`Directory.Build.props`. The repository carries a copy of Enigma.Msi's worker CLI.

## Context & constraints

- **The model is Enigma.GitClient's** `packaging/windows/` at `a58d8fe`:
  - `buildmsi.ps1` and `buildmsi.bat`;
  - `Enigma.Msi.Worker/` (20 binaries and a README);
  - the `.gitignore` entry for `.wixsharp/`;
  - `WindowsInstallerIdentityTests`;
  - the `DisplayNameConsistencyTests` and `AssemblyNameConsistencyTests` additions;
  - the README *Windows installer* section.
- **The worker:** GitClient vendors Enigma.Msi `1.7.0` (`a7a1bfb`), built against WixSharp_wix4 2.14.2. Its
  20 binaries are byte for byte `C:\Dev\EnigmaLibs\Enigma.Msi\src\Enigma.Msi.Worker\bin\Release\net472\`
  (checked while planning). The `.exe.config` differs only in line endings. `1.7.0` is still Enigma.Msi's
  latest tag.
  - Its command is `Enigma.Msi.Worker.exe build <file.msipkg.json>`. Exit codes: `0` built, `1` invalid
    profile or failed build, `2` bad invocation.
  - It needs the WiX CLI on the `PATH` (7.0.0 is installed here) and .NET Framework 4.7.2.
- **No Enigma File Explorer MSI exists.** The registry's uninstall keys list Git Client, Text Editor,
  Markdown Editor, Launchpad and Msi, but no File Explorer. So the upgrade code is new. It was generated
  while planning with `[guid]::NewGuid()`: **`6b9404a4-3818-4205-b6c2-bc3befe8c3eb`**. It matches no
  sibling app's code (checked against GitClient's script and every `*.msipkg.json` under `EnigmaLibs`).
- **Identity:**
  - `ProductInformation.DisplayName` is "Enigma File Explorer";
  - the assembly is `Enigma.FileExplorer.Desktop`;
  - `<Authors>` is "Josué Clément";
  - the version is `<Version>` in `Directory.Build.props` (0.2.0 today; FEATURE-27BF makes it 0.3.0).
- **Publish** (FEATURE-E5D8): `packaging/windows/publish.ps1` runs
  `dotnet publish src\Enigma.FileExplorer.Desktop -c Release -r win-x64 -p:PublishReadyToRun=true` and
  exits with dotnet's code. The result is `src\Enigma.FileExplorer.Desktop\bin\Release\net10.0\win-x64\publish\`,
  with `app.ico` beside the exe (FEATURE-5050).
- **Git rules for the vendored files:**
  - `.gitignore` ignores `artifacts/`, `*.pdb`, `[Bb]in/`, `x64/` and `[Rr]elease/`. The vendored
    folder must match none of them, because `git clean -dxf` deletes ignored files;
  - `.gitattributes` marks `*.dll` / `*.exe` binary and `*.bat` CRLF.
- **The `.ps1` stays ASCII.** Windows PowerShell 5.1 reads a script without a BOM in the ANSI code page,
  and `.editorconfig` asks for UTF-8 without a BOM.
- **Tests:** the Desktop tests run on this machine. `PackagingScriptsTests` already ties the packaging
  files to the assembly, and `RepositoryRoot` finds the solution.
- **The run may not run `git clean`** in this repository, so the script is verified end to end in a
  scratch clone.

## PHASE01 — Vendor the Enigma.Msi worker CLI

**Branch:** `feature/feature-5447-phase01-vendor-msi-worker`
**Status:** DONE

### Steps

1. Copy the 20 binaries of `C:\Dev\EnigmaLibs\Enigma.GitClient\packaging\windows\Enigma.Msi.Worker\`
   into `packaging/windows/Enigma.Msi.Worker/`, without `.wixsharp/` if it is there.
2. `packaging/windows/Enigma.Msi.Worker/README.md`: GitClient's, with `Enigma.GitClient` changed to
   `Enigma.FileExplorer` in the MSI's name. The rest stays: source, exit codes, requirements, licences
   and how to refresh it.
3. `.gitignore`: `packaging/windows/Enigma.Msi.Worker/.wixsharp/`, with GitClient's comment.
4. Check two things:
   - `git status --porcelain --ignored -uall` lists every vendored file as untracked, none as ignored;
   - the worker runs: with no arguments it prints its usage and exits 2.

### Acceptance criteria

- Every vendored binary is identical to GitClient's copy and to Enigma.Msi's `bin/Release/net472/`
  output (`cmp`). The `.exe.config` may differ only in line endings.
- No vendored file is git-ignored; `.wixsharp/` is.
- `Enigma.Msi.Worker.exe` with no arguments prints its usage and exits 2.
- The build has zero warnings. The whole suite shows no new failure.

## PHASE02 — The buildmsi script

**Branch:** `feature/feature-5447-phase02-buildmsi-script`
**Status:** DONE

### Steps

1. `packaging/windows/buildmsi.ps1`: GitClient's script with these changes:
   - `$UpgradeCode = '6b9404a4-3818-4205-b6c2-bc3befe8c3eb'`;
   - `$ProductName = 'Enigma File Explorer'`;
   - `$Assembly = 'Enigma.FileExplorer.Desktop'`;
   - the MSI and profile base name `Enigma.FileExplorer.$version`;
   - the help text names Enigma File Explorer and its paths.
   It stays ASCII, and the manufacturer stays `[char]0x00E9`.
2. `packaging/windows/buildmsi.bat`: GitClient's, with the names changed. It runs `buildmsi.ps1` through
   `powershell -NoProfile -ExecutionPolicy Bypass -File` and passes the exit code on. It is CRLF.
3. Tests (Desktop):
   - a new `WindowsInstallerIdentityTests`:
     - the script holds `$UpgradeCode = '6b9404a4-…'`;
     - it holds `$ProductName = '<ProductInformation.DisplayName>'`;
   - `PackagingScriptsTests`: the script holds `$Assembly = '<AssemblyName>'`. The class comment names
     the Windows installer.
4. `README.md`:
   - a *Windows installer* section after *Build, run, test*, as GitClient's;
   - the *Solution layout* row for `packaging/windows` names the installer and the worker.
5. Verify in a scratch clone:
   1. commit the dev's tree there;
   2. run `buildmsi.bat`;
   3. read the MSI's `Property`, `Directory`, `Shortcut`, `Upgrade` and `Icon` tables.
   Also check that a missing `wix` stops the script before `git clean` (a canary file survives).

### Acceptance criteria

- In the scratch clone, `buildmsi.bat` exits 0 and leaves `artifacts/Enigma.FileExplorer.<version>.msi`
  and its `.msipkg.json`. After it, `git status --porcelain` is empty.
- The MSI's tables show:
  - `ProductName` "Enigma File Explorer", `Manufacturer` "Josué Clément", `ProductVersion` = the
    `Directory.Build.props` version;
  - `UpgradeCode` `{6B9404A4-3818-4205-B6C2-BC3BEFE8C3EB}`, `ALLUSERS` 1, `ARPPRODUCTICON` set;
  - `INSTALLDIR` "Enigma File Explorer" under `ProgramFilesFolder`;
  - two "Enigma File Explorer" shortcuts (`DesktopFolder`, `ProgramMenuFolder`) on
    `[INSTALLDIR]\Enigma.FileExplorer.Desktop.exe`, each with an icon.
- The profile says `"compression": "None"`.
- With no `wix` on the `PATH`, the script stops before `git clean` and its message gives the install
  command.
- `diff` against GitClient's `buildmsi.ps1` / `.bat` shows only the names, the constants and the help
  text.
- The build has zero warnings. The whole suite, with the new tests, shows no new failure.
